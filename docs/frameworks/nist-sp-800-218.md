# NIST SP 800-218 — engagement guide

> Original operational guidance, not a release approval or a secure-development
> attestation. Track the [NIST SSDF publication status](https://csrc.nist.gov/Projects/ssdf/publications).

## Engagement focus

Map the actual delivery lifecycle across developed, acquired, configured, and
open-source software. Define practical engineering expectations and exception
handling; review representative releases from intent through delivery; inspect
vulnerability learning loops; include suppliers and components; and report
coverage, meaningful exceptions, and improvement commitments.

## Roles and annual rhythm

Product, engineering, security, and release teams own lifecycle records and
release decisions. Independent reviewers sample for repeatability. AI connects
approved work items, code changes, builds, releases, and findings; it cannot
approve a release, generate attestations, or send sensitive artifacts to
an unapproved model. Improve quarterly and review annually.
